# ADR 0018: Version roster areas, groups and weekly templates

Status: accepted for implementation. Parent: #1036 / #979. Extend workforce under ADR-0005 and pin ADR-0017 shift revisions.

## Requirements and evidence

Read-only legacy review on 2026-10-14 confirmed: areas have code/description/active/applicable shifts; groups have a name and multiple shifts; weekly templates have name/active, seven weekdays, first/second shift and area, and weekly-off. Roster settings select automatic population (all/fixed-shift employees) and an effective weekday. No source values or saved actions are copied. Standard/custom is the legacy shift-definition classification; the existing day/evening/night/rotating/on-call classification is an intentional working-time label, not a claim to reproduce that legacy enum. One canonical code replaces the legacy short-code alias. Dated rosters and automatic population will implement the remaining setting semantics separately.

Planning assumptions, not measured demand: 1,000 hospitals × 100 configuration heads = 100,000 heads at 12 months; monthly revisions at 36 months are 3.6 million snapshots, with ≤100 members or ≤14 weekly allocations per revision. Peak 50 configuration reads/s and 5 writes/s, 10:1 read/write, ≤16 KiB request payload and ≤100 returned heads/page by default (platform hard maximum still applies). Target shared-platform availability 99.9%, configuration p99 <500 ms. Keep one indexed PostgreSQL; no new service/cache/shard or idle workload cost. Storage grows with attributable history; no unbounded input/list or N+1 loads. These targets require later representative-load measurement; a few synthetic fixtures are not a benchmark.

## Decision

Use one stable typed configuration head and immutable revision aggregate for `area`, `group`, `weekly_template`. Normalized revision membership and weekday tables retain exact shift/area revision references. Code/kind/scope are immutable; case-normalized names/codes are unique within tenant/hospital/kind. Each revision has an explicit effective date and authenticated reviewer provenance. A manager must explicitly confirm review; no source policy defaults are adopted. New admission requires active current references; preserved historical pins remain readable and usable for unchanged membership. Retired configurations cannot be newly selected. Reactivation or changed effective dates require fresh active references.

A weekly template has seven distinct Monday=0…Sunday=6 day rows, zero allocations on weekly-off days, one/two on working days and at least one working day. Each allocation pins an area revision and a shift revision included in that area. A weekly template cannot become effective before the pinned area revision. The editable catalogue admits current active references; dated allocation will add an as-of resolver for effective policy history. Validate conflicts across the complete seven-day cycle, including Sunday overnight → Monday and overnight overlap into a weekly-off day. Adjacent intervals may touch; overlaps cannot be saved. Definition duration is wall-clock; dated roster publication requires a reviewed hospital IANA timezone and explicit DST handling and cannot treat template duration as paid time.

The header/revision FK is deferred so one transaction writes the head, snapshot and normalized members. Each child must be inserted in its parent revision's creating transaction; later INSERT, UPDATE, DELETE or TRUNCATE cannot alter history. Deferred aggregate checks enforce the day/membership rules at commit. Foreign keys include tenant/hospital and constrain template area references to an actual area revision. Stable UUID PUT, expected version, per-ID advisory serialization and DB uniqueness protect concurrent retries. Unchanged requests return the prior result without new history/audit/outbox.

Assets: scheduling integrity, hospital policy and future staffing records. Threats: foreign tenant, sibling hospital, stale editor, unauthorized reader and insider rewriting history. Authenticated tenant membership plus explicit hospital grants protect reads. `workforce.roster.manage` AND a locked hospital manager grant protect writes; the actor/reviewer comes from authenticated context. Forced RLS covers all four tables. Input cannot supply tenant, hospital, reviewer or object keys. Private no-store applies; events/audits contain identifiers/version only. Multi-hospital ownership grants no implicit sharing.

One commit records state/revision/members, append-only audit and `helivanta.in.workforce.roster_config_changed.v1` outbox. NATS JetStream publishes after commit and retries during outage; HTTP success does not claim consumer completion. No network call is held inside the transaction. PostgreSQL/auth failure fails closed. Valkey remains safe technical state, not authoritative scheduling/HR cache. Temporal is used later for durable approvals/timers/multi-step file release/payroll; a single configuration transaction does not require a workflow.

## UI and delivery

Shared selectors display pinned shift/area names and timings; paged catalogs have explicit loaded-filter scope, accessible loading/empty/retry states and reader-only controls. Editor automatically reveals/focuses, preserves invalid/conflicting input and keeps its UUID during retries. Hospital/type changes destroy stale editor state. History shows the original effective date, membership and timings.

Migration 0006 is additive empty tables/indexes/triggers only, with bounded DDL timeouts and no customer backfill. GitOps uses current build/base images → deployment branch → Kargo → Argo. Rollback retains new data/schema and removes endpoint availability in the older API; no destructive down migration. Physical CNPG restore replays persisted data without SQL insert triggers. A privileged logical restore must load/validate snapshot children in a controlled trigger-disabled restore session before reopening service; application roles cannot use that path.

Verify real PostgreSQL transaction/admission/version/retry/unique/invalid-reference/overlap/off-day/history-append/role/tenant/hospital behavior, full stack checks, isolated CNPG, real UI and deployed API/UI/logs. Keep #1036 open for dated allocations, setting semantics, conflicts with approved leave/qualification and draft/freeze/correction workflows.
