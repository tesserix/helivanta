# ADR-0034: Bounded, scoped pharmacy stock CSV exports

18 October 2026. Story [#1232](https://github.com/tesserix/helivanta/issues/1232), reporting parent #1060 and stock parent #162.

## Context and operating assumptions

Storekeepers need an auditable file of all matching register positions, including unloaded pages. The legacy SALES STOCK REPORT (755) exposes item code, unit and stock quantities; existing read-only evidence is in #1060 and `docs/requirements/pharmaconnect-legacy-procurement.md`. Its sales/margin/indent semantics are not implemented by this export. No customer rows are copied.

Planning assumptions, not benchmark claims: peak one export/second across the platform and one per minute per active outlet, on top of the existing 20 stock reads/second. Expect 500 rows / roughly 640 KiB per ordinary export and at most 1,000 rows / 8 MiB. Export reads do not change inventory (read:stock-write ratio effectively unbounded for this endpoint); existing ledger assumptions remain 2 million / 6 million rows at 12 / 36 months. Targets are 99.9% monthly availability, p99 under five seconds for a typical export and a ten-second database/request deadline. Representative-volume validation is required before claiming these targets. No infrastructure resource is added; marginal cost is a scoped aggregate, bounded memory and download bandwidth.

## Decision

Add `GET /pharmacy/pharmacies/{pharmacy}/outlets/{outlet}/stock/positions.csv` under the existing stock-read permission. Reuse the existing position query and cutoff/expiry/location/product/lot/balance validation (the lot filter, `batch_id`, was added with #1303 so the register can reopen one position); do not copy the SQL, add a stock master or infer availability. The export refuses unsupported, repeated or pagination filters. Fetch one bounded query with a 1,001-row overflow probe; refuse over 1,000 rows or 8 MiB with an explicit error before any attachment bytes. Buffering this bounded file permits clean all-or-error responses; streaming arbitrary results would allow partial, misleading files after a database failure.

Use the same deterministic position ordering as the register. CSV contains identifiers, current product/location/address metadata, exact base-unit decimal quantities and outlet-local expiry metadata at an explicit UTC cutoff. Unknown coordinates stay blank. Empty results contain headers only. There is no cross-unit total, valuation or sales figure. CSV text fields are escaped with the standard CSV encoder and formula-like values are prefixed with an apostrophe; numeric fields are written from server-owned numbers/decimal totals. Consumers should import identifiers/long decimals as text when spreadsheet autoformatting would lose fidelity.

Every request requires verified session/tenant membership, `pharmacy.stock.read`, live reader/editor outlet access, scoped references and FORCE RLS. Pharmacy affiliation grants nothing. Assets are stock/commercial metadata and staff attribution; threats include anonymous requests, other tenants/outlets and revoked insiders. The server authorizes before reading; the browser's disabled button is not a security control. Return no-store, nosniff and a server-generated ASCII attachment name. Record the actor, opaque scope identifiers, cutoff, row count, SHA-256 and request correlation in the existing structured audit stream (`audit_event=pharmacy.stock.exported`), with no exported cell values or names. This is a generated-response audit, not proof the user retained or opened a downloaded file. Failed requests never emit a success audit.

The UI downloads through the existing same-origin authenticated API client and expected-tenant header, with an abort signal. Changing outlet/tenant/filter/cutoff unmounts and aborts the old export; no late response may trigger a stale download. Feedback is accessible, duplicate clicks are disabled and failure permits an explicit retry.

## Consistency, failures and delivery

One SQL statement produces each file, so it cannot drift between paginated requests. This is recorded-time reporting: transactions begun before cutoff can commit later with an earlier movement timestamp; product/location metadata is current. A repeated request can therefore differ as transactions commit or current labels change. It is not a durable stocktake snapshot or formal period close; those require their own persisted contract. Repeat download requests never mutate stock, payables or files. Each successful HTTP generation has its own audit entry; no command deduplication table is needed.

PostgreSQL and live authorization are critical: failure or timeout returns an explicit error and no CSV. There is no cache or stale fallback. The existing Valkey rate limiter still applies. No NATS event/consumer, Temporal workflow or GCS file is needed for a synchronous read. Offline exports, BI subscriptions and scheduled reporting remain separate work.

The change adds an API route and UI only, with no schema migration. Roll back via GitOps to the preceding application image; existing inventory and audit retention are untouched. Keep #1232 open until the reviewed release and deployed acceptance, and keep all broader unfinished parents open.

A real 5,000-position synthetic fixture exceeded the ten-second request budget on the local non-bypass-RLS database. The synchronous bound was reduced to 1,000 rather than relaxing the deadline or authorization. The byte guard is tested directly at the encoder boundary; broad unfiltered reports may still time out and must return an error, never a partial file. Larger exports need a separately designed asynchronous path and representative-volume work.

Authenticated read-only legacy refresh on 18 October 2026 confirmed StoreHome stock date, Managed/Expired/Unmanaged states, store/category/subcategory/manufacturer filters, item name/code, batch/expiry, MRP/EPR, rack/shelf and stock. ItemLedger exposed purchase department, item category, store, current/old stock, item, batch and Download. No legacy download, stock change or transaction was executed, and no row values were copied. These labels inform coverage; they do not prove legacy formulas or permissions.

A failing 1,000-position fresh-table test then exposed a nested-loop plan repeatedly rescanning outlet-wide RLS-filtered references. The shared register query now bounds unique-key batch/location/product lookups with lateral LIMIT 1, retaining every tenant/outlet predicate and RLS check. The same fixture exports all 1,000 rows, retains the JSON 50-row page/more indicator and rejects row 1,001. A diagnostic EXPLAIN ANALYZE under the non-bypass application role measured 129.259 ms SQL execution for this synthetic shape; temporary diagnostic code was removed. This is not a representative product-count or historical-volume benchmark, and larger/different shapes can still fail the unchanged ten-second deadline.
