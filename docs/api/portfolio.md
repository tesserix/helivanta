# Product ownership and coverage

[Contract index](README.md) · 2026-10-22 · current implementation distinguished from target

The application currently runs one Go API containing ten registered modules and one Next.js staff application. Separate product APIs are the proposed direction in [ADR-0007](../adr/0007-product-api-target-architecture.md). Preserve module ownership while documenting and extracting complete vertical slices; a new documentation section does not establish a new deployed service.

Current route coverage is exhaustive for the registry, not a claim of complete product acceptance. See [generated evidence](reference/README.md). Existing SQL migrations define storage, Go HTTP types define current wire behavior, and the JSON contracts generate selected Go/Zod types. These are currently several sources of authority, not one comprehensive OpenAPI-first pipeline.

## Non-negotiable reference relationships

- `tenant_id` is verified session context. Hospital, outlet, premise, base and receiving-facility IDs select narrower scopes and require current grants.
- Patient identity owns patient registrations and local MRNs. A matching name or phone is not a permission grant, unique person identifier or automatic merge instruction.
- The drug master owns coded drug identity, schedule class and pack facts for every tenant (#476). Consumers store the formulation or product **version** id they acted under; they never copy or edit the catalogue.
- MediCore owns encounters and prescriptions; PharmaConnect owns dispensing and pharmacy stock; LabConnect owns released diagnostic result versions. Each publishes facts for authorized consumers.
- SupplyConnect owns central-store inventory; PharmaConnect owns outlet inventory. Transfer is linked source and destination postings with reconciliation, not shared writes.
- Hospital billing and pharmacy operational payables are different ledgers. A statement or dashboard cannot create a second financial source of truth.
- Commercial CRM owns leads and pipeline under issue #808. Hospital patient engagement and emergency coordination have separate clinical/operational access requirements.
- An entitlement, professional role, organizational affiliation, route permission and object grant are separate decisions. Do not infer one from another.

## Scale and availability

Reuse the explicit planning assumptions in [system design](../architecture/01-system-design.md): 50/150 tenants at months 12/36, 1,000/3,000 peak RPS, 80:20 reads:writes, typical 2–20 KB JSON and a 30% hot-tenant test. At 500 encounters/tenant/day and 40 KB each, structured encounter data alone is about 365 GB in year one for 50 tenants, before indexes, replicas and attachments; a constant 150-tenant population over three years would be about 3.3 TB. These are sizing exercises, not measured usage forecasts.

The existing target defines service objectives and recovery/cost assumptions. Product owners must approve route-specific budgets, retention and supported payload volumes before implementation or extraction. Contract documentation adds no deployment cost; independent runtime cost requires the existing architecture's sizing and operations review.
