# Evidence, legacy mapping and references

[Architecture index](README.md) · Review date: 2026-10-13

## What was actually reviewed

This design combines repository inspection, the existing [Exploration epic #979](https://github.com/tesserix/helivanta/issues/979), a fresh read-only browser check of the user-supplied legacy system and official technology/compliance references. It does not infer production implementation from old design documents or from a menu being present.

The source is a production hospital application. This public repository contains only sanitized workflow descriptions: no source host/address, patient/staff names, record identifiers, operational totals, raw browser captures or credentials. No clinical, stock, billing, account, message, export or configuration operation was submitted.

## Open discovery gaps

Legacy transactional behavior, clinical scoring, statutory finance calculations, saved-record-only screens, seven unresolved reports noted in the epic, external provider behavior and all migration/restore behavior need synthetic or otherwise authorized verification. Group sharing and CRM are requested target requirements, not capabilities proven by the legacy walkthrough. Hospital count, legal-entity boundaries, existing record ownership and real workload distributions must be established before migrating live records.

## Confirmed follow-up technology decisions

The user confirmed NATS with JetStream and Temporal, then multi-tenant GCS file storage and ClamAV scanning. These are design decisions, not claims of deployment. Supporting references: [NATS JetStream](https://docs.nats.io/concepts/jetstream), [GCS uniform bucket-level access](https://cloud.google.com/storage/docs/uniform-bucket-level-access), [GCS signed URLs](https://cloud.google.com/storage/docs/access-control/signed-urls), and [ClamAV scanning](https://docs.clamav.net/manual/Usage/Scanning.html).
