# PharmaConnect retail counter: production acceptance test plan

Date: 2026-11-09. Written against main `9a674a98`.

Every label, message and status here was read from source at that commit; none has yet been seen in a running app. Where a case and the running app disagree, record the difference as a defect. Do not change the expected result to match the app.

## 1. Purpose, scope and the lock

**Purpose.** Prove the retail counter is ready for production before it is locked. Once every case here passes, or each failure is fixed or accepted in writing, the scope below is signed off and frozen.

**In scope** (the shipped retail counter):

- setup and access: pharmacy, outlets, outlet grants, GST registration, drug licences and their evidence, hospital affiliation
- catalogue, schedule class, item categories, HSN classification, NPPA ceilings, discounts and service charges
- stock: locations, batches, receipt, correction, release, batch safety, register, reconciliation, overview and CSV
- prescriptions and prescription images
- the counter sale: walk-in, registered patient, OPD visit and admission sales; cash, verified UPI, reference UPI and card; the GST invoice; and failure recovery
- after the sale: returns and credit notes, the unused-UPI refund, the sales worklist, daily and sales reports, CSV exports, the H1 and prescription registers, the dispense queue and medications, and accounts (payables and settlements)

**Out of scope** (not built; see section 13): the supply chain (#1133), hospital bill mapping (#1051), margin reports, GST reconciliation reports (#1061), Schedule X and NDPS, generic substitution, patient ordering and delivery, e-invoicing, and the AI features.

**What "locked" means.** After sign-off:

- **Recorded:** the signed commit SHA and image digests, in section 15.
- **Changes need a new issue.** Any change to in-scope behaviour cites the case IDs it affects. Those cases are re-run before the change reaches production, and the result is added to section 15.
- **Bug fixes.** A bug fix inside the locked scope adds an automated test for the case that found it.
- **Never loosened.** No refusal in this plan is loosened without a new sign-off.

  - `OTC1`: schedule class none.
  - `G1`, `H1P` and `H1X`: classes G, H and H1.
  - `X1`: class X. `ND1`: class none with NDPS true.
  - `NPPA1`: price-controlled, ceiling per unit below MRP per unit.
  - `TAX0`: exempt. `TAX5`: 5%. `TAX12`: 12%.
- **Batches at outlet A:**
  - normal: expiry at least 6 months away
  - `EXP-TODAY`: expires on the outlet's date today
  - `EXP-TMRW`: expires tomorrow
  - `SAFE1`: will receive a safety incident
- **Locations:** quarantine `Q1` and sellable `S1` at A; quarantine `QB` at B.

**Recording.** For each case, record: ID, Pass, Fail or Blocked, the actual result if it differs, and the date, tester and build SHA. Attach a screenshot for every Fail. A Fail is a defect with a GitHub issue, linked in the run sheet.

**Severity:** S1 means wrong money, tax, stock or regulated record, a data leak, or loss of data. S2 means a required flow is impossible. S3 means a wrong message or a confusing screen with a workaround. S4 is cosmetic.

**Exit criteria:**

- **Passed:** every case passes.
- **Failures:** each Fail is fixed and re-tested, or at S3/S4 accepted in writing.
- **Defects:** no S1 or S2 is open.
- **Findings:** every finding F-x has its decision recorded.
- **Gates:** G-1 to G-4 are met.
- **Automated suite:** green on the signed SHA (section 14).

## 5. Common refusal rules (apply everywhere)

Check these once per area, as directed by the section 12 cases. They are the rules most likely to be scripted wrongly.

| Rule                                                                 | Expected                                                                            |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Route permission missing                                             | 403 `missing permission {perm}`                                                     |
| No outlet grant, another outlet, another pharmacy, or another tenant | **404** "pharmacy resource" (never 403, never the record)                           |
| A write with only a `reader` grant                                   | **404**, not 403                                                                    |
| Grant lookup unavailable                                             | 503 `authorization_unavailable` "pharmacy access is temporarily unavailable"        |
| Workspace changed in another tab                                     | 409 `session_changed` "Your workspace changed. Refresh the page before continuing." |
| Unknown JSON field                                                   | 400 "invalid catalogue request"                                                     |
| Two JSON objects in one body                                         | 400 "expected one JSON object"                                                      |
| An id that is not a UUIDv7                                           | 404                                                                                 |
| Same id, same body, same person                                      | 200 with the stored record (first write 201)                                        |
| Same id, different body or person                                    | 409 (message varies by resource)                                                    |
| Missing outlet grant for a tenant admin                              | 404: administration does not imply operational access                               |
