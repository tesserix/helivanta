### #854 — HMS renders its own login form

HMS is now Zitadel's **login client** for the `hms-web` app: our page, our theme,
no vendor-branded page at any point. Verified on a fresh clone including a real
token exchange, 11/11 e2e, and seven main-frame document commits all on HMS's
origin.

The reversal of D5a is deliberate and priced — see the spec.

### #848 — idle timeout

A session with no human interaction for 15 minutes stops being usable. The
`idle_deadline` is a signed claim enforced by `authn.Middleware`, so a killed
tab, a suspended laptop or a stolen cookie in `curl` all fail closed. Tracking
and the two-minute warning live in `@hms/ui`, so every zone app inherits them.
Teardown is this browser only, never subject-wide (#781's semantics).

### 1. #45 — secrets management *(blocks production entirely)*

HMS now holds **three** boot-refusing secrets and only dev paths exist:

| Secret | If wrong |
|---|---|
| `SESSION_SIGNING_KEY` | mints every session — a leak is credential forgery |
| `ZITADEL_LOGIN_CLIENT_TOKEN` | **instance-level**; can finalise an OIDC auth request for *any* Tesserix product |
| `HELIVANTA_WEB_ORIGIN` | API refuses to boot outside dev |

**Confirm the backend decision first.** There is a prior note that the platform
workstream chose **OpenBao over GCP Secret Manager, fleet-wide, with HMS as the
pilot**, but no spec for it exists in `docs/superpowers/specs/`. If that is
settled, #45 is "implement the pilot"; if not, the decision comes first.

### 2. #54 — audit trail *(now unblocked)*

#848 was its prerequisite: attribution is only trustworthy once an inherited
session cannot act as someone else. Still has **no milestone**, and gets more
expensive per module that starts writing PHI.

**Binding constraint:** attribute to an **HMS-owned identifier**, with the
Zitadel `sub` as an attached credential, not the key. HMS changed identity
providers this week; GIP and Zitadel subjects are unrelated values, so a trail
keyed on the IdP's subject would already be silently corrupt. Audit records
cannot be rewritten — this is decided at design time or not at all.

### 3. Filed this session, all real

- **#861** — nothing throttles requests *before* authentication. `V1Chain` parses
  the token in step 1 and starts throttling in step 3, because the limiter keys
  on a principal that does not exist yet. Correct ordering, but every pre-auth
  defect is unbounded. The hard part is keying fairly when a hospital shares one
  NAT'd egress IP.
- **#856** — Zitadel signals `passwordChangeRequired` to a login client nowhere
  in the flow (verified live), so HMS silently completes those logins.
- **#859** — a cookie whose `exp` has lapsed loses its idle deadline, so a
  wake-from-suspend renewal earns a fresh window. Needs a `pkg/session` API able
  to surface a deadline from a token the verifier refuses.
- **#855** — no account lockout. Its original premise was **wrong and has been
  corrected**: Zitadel *does* throttle, ~0.78s flat for 9 attempts then +1s per 5.
- **#858** — autofilled inputs ignore the theme; near-white fields on the dark
  login card. Cosmetic, but it is what every clinician with saved credentials sees.

## Production prerequisites — none live in this repo

1. **`ZITADEL_LOGIN_CLIENT_TOKEN`** on the shared instance (gated on #45)
2. **`loginV2.required=false`** on that instance. With it `true`, the
   instance-wide login URL silently overrides the per-app one (upstream
   zitadel/zitadel#10722). Consequence: any other product relying on that flag
   *implicitly* falls back to its own per-app setting.
3. **`HELIVANTA_WEB_ORIGIN`** outside dev, or the API will not start.

## Things that will bite you

**Leftover `next dev` processes are the top local-dev hazard.** A surviving
process holding a port makes turbo fail the whole group, and it presents as *"the
app is broken"* rather than *"the port is taken"*. This cost over an hour.
Killing `apps/shell`'s dev server also cascades through turbo's process group and
takes medicore/lab/pharmacy with it. `scripts/e2e.sh` cleans up after itself; do
that manually otherwise.

**Next 16 allows one dev server per project directory.** This is why the
idle-timeout e2e fixture cannot run alongside the main stack, and why
`make e2e` exists as two phases. A bare `playwright test` runs 11 and
deliberately excludes the idle project.

**A 200 from Zitadel does not mean it did what you asked**, and a `GET` may not
show you the truth. `PUT .../oidc_config` is a **full replace** — a partial PUT
silently reset `authMethodType` and nobody could complete a sign-in, while the
config read back as correct because `authMethodType` is *elided* from the
response. Same elision hides `forceMfa` when false.

**Zitadel does not enforce `forceMfa` for a login client.** A password-only
session was accepted and a valid authorization code issued. Factor enforcement is
HMS's job — `loginclient/sufficiency.go`, guarded by an arch test.

**GitHub Actions is billing-blocked**; jobs fail in seconds. **GitGuardian** fires
on the *word* "password" in field names and comments — 11 false positives on
#857, clean on #860. A real leak would look identical to that noise; an ignore
rule for those paths would restore the signal.

**The coverage gate is flaky under container load.** Re-run before chasing.

## How this work has been running, and why

- **One subagent per task**, reviewed independently before the next is dispatched.
- **Every assertion observed failing before it is trusted** — and this session
  sharpened that rule. **Nine proofs looked like evidence and were not**, because
  the mutation did not move a value the assertion reads: zeroing a constant the
  test compares against itself; probing a detector on a dimension it does not
  inspect; dispatching a synthetic `scroll` at `window` when `scroll` does not
  bubble and the app scrolls in an inner container. **Two of those were defects in
  plans I wrote.** Ask of every mutation: *does this change a value the assertion
  reads?*
- **Running it beats reviewing it, and the gap is not small.** Two #854 defects
  survived five careful reviews because they lived *between* diffs: a config
  change broke a seed script nobody re-ran, and the `authMethodType` reset above.
  Only redeeming an authorization code found the second. `make verify-local` now
  drives a full token exchange for exactly this reason.
- **Reports contain factually wrong claims, including mine.** I told the user the
  login chain worked end to end; it produced an authorization code that could not
  be redeemed. State what you checked and mark the rest unchecked.
