# Run and check the e2e suite in CI (#920) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The specs written to catch #916's defect class are run by CI on every PR, and the directories holding them stop being invisible to the documented gate.

**Architecture:** A new `e2e` job in `ci.yml` brings up the real dev stack with `docker compose`, seeds it, starts the API and shell, and runs `make e2e` under a hard timeout with no retry. `e2e/` gains the three missing package scripts; `scripts/` gets a deliberate coverage decision.

**Tech Stack:** GitHub Actions (ubuntu-latest), Docker Compose, pnpm/turbo, Playwright, Go 1.26, Node 22.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-20-e2e-in-ci-design.md`. D1–D6 refer to it.
- **No GitHub secrets** (D3). Every dev-stack credential is a committed literal or generated at first boot. If a step seems to need a secret, that is a signal something is wrong — stop and report.
- **No retry, no `continue-on-error`, no soft failure** (D2). A flake must stay visible. #923 fixes the known one.
- **The job must be observed failing** before this is done (D6). A gate never seen red is decoration.
- **Prove every assertion can fail**, and confirm the mutation actually landed before trusting what the run then says.
- **Commit messages:** single line, conventional commits, no signature, no `Co-Authored-By`.
- Pushing branches runs Actions minutes; that is expected and acceptable while the repo is public.

### Task 1: Prove `*.localhost` resolves on an Ubuntu runner — SPIKE, do this first

**Files:** a scratch workflow, deleted before the branch merges.

**Why first.** The whole harness depends on `helivanta.localhost` and
`auth.tesserix.localhost` resolving to loopback for `curl`, `node`, Go and
`preflight.sh` — not just for Chrome, which resolves `*.localhost` itself.
Verified on macOS, **unverified on Ubuntu** (D4). If it does not resolve, every
later task is built on sand.

**Steps:**
- [ ] Add a temporary workflow that, on `ubuntu-latest`, reports: `getent hosts helivanta.localhost`, `curl -sS -o /dev/null -w '%{http_code}' http://helivanta.localhost:PORT` against a trivial local listener, `node -e "require('dns').lookup('auth.tesserix.localhost', console.log)"`, and whether `systemd-resolved` is running.
- [ ] Push, read the actual output. **Record the literal result** — this is a measurement, not a prediction.
- [ ] If it does NOT resolve: add `/etc/hosts` entries as an explicit job step and re-run the probe to prove the fix works. Do not assume the entry format works — observe it.
- [ ] Delete the scratch workflow before the branch merges. Its result goes in the task report and the PR body.

**Verification:** the recorded runner output, quoted.

### Task 3: The `e2e` CI job

**Files:** `.github/workflows/ci.yml`

**Interfaces:** Consumes Task 1's resolution answer.

**Context the implementer needs.** `make e2e` assumes the stack is already up.
The full prerequisite chain, from the investigation:
`preflight.sh` → `docker compose up -d --wait postgres nats redis openfga` →
`up -d zitadel-db zitadel zitadel-login zitadel-proxy` → poll Zitadel healthz →
`preflight.sh --only zitadel-instance-domain` → `zitadel-bootstrap.mjs` →
`migrate` → `seed-dev.mjs` → `dev-api` + `dev-web`. Then `make e2e` runs its
three phases, stopping and starting fixture stacks between them.

**Steps:**
- [ ] Add an `e2e` job to `ci.yml` triggered on the same events as the existing jobs (D1: every PR, every `main` push).
- [ ] Reproduce the prerequisite chain. Prefer calling the existing `make` targets over reimplementing them — a CI-only copy of the startup sequence will drift from the one developers use, and the drift will be silent.
- [ ] Install Playwright browsers (`pnpm --filter e2e exec playwright install --with-deps chromium`) and cache what is worth caching.
- [ ] **Hard `timeout-minutes`** on the job — comfortably above expected runtime, far below 66 (D2). Argue the number in a comment.
- [ ] **On failure**, dump `docker compose -f docker-compose.dev.yml ps` and the `zitadel-login` logs, so a hang reads as a cause rather than a timeout (D2).
- [ ] Upload the Playwright report/traces as an artifact on failure.
- [ ] **No `continue-on-error`, no retry, no `|| true`.** Anywhere.
- [ ] Record the job's real wall time from the first green run, and put it in the PR body — D1 accepted "roughly 8-10 minutes" as an estimate; replace it with the measurement.

### Task 4: Observe the job failing (D6)

**Steps:**
- [ ] On the branch, break something the suite genuinely asserts — a real assertion, not a syntax error, so the failure exercises the reporting path.
- [ ] Push. **Watch the job go red.** Record the literal failure output and confirm the diagnostic dump appeared and was useful.
- [ ] Revert, confirm the revert landed by re-reading the file, push, watch it go green.
- [ ] Also confirm the timeout path behaves: either observe it, or state plainly that it was not observed and why. Do not claim it works untested.
