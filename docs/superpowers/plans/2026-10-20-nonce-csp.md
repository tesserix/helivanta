# Nonce-based CSP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce a per-request nonce Content-Security-Policy on every shell
HTML response, with violation reporting (#1113).

**Architecture:** The middleware mints a nonce and sets the policy on request
and response. The root layout reads the nonce, which makes every route
dynamic, and passes it to the inline scripts and to `get-nonce`. A public
route handler logs violation reports with sanitised fields.

**Tech Stack:** Next.js 16.4 App Router (Turbopack), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-20-nonce-csp-design.md`

## Global Constraints

- Enforced `Content-Security-Policy`, never `-Report-Only` (spec D1).
- Nonce: 16 bytes from `crypto.getRandomValues`, base64, one per request (D2).
- The policy string is exactly the one in D2. `'unsafe-eval'` appears only
  when `NODE_ENV === "development"`.
- No `'unsafe-inline'` in `script-src` or `style-src`. `style-src-attr
'unsafe-inline'` is the only `'unsafe-inline'`.
- No URL query or fragment reaches a log line (anti-goal).
- Node: the v24.21.0 binary on PATH, plus the two `NEXT_PUBLIC_ZITADEL_*`
  variables for builds (memory: frontend pipeline).
- Gates: `pnpm turbo lint type-check test build format:check` and
  `make lint-shell`.

## Review Focus

1. **A route that renders but escapes the nonce:** `not-found`, `error.tsx`,
   the `/api/auth/callback` page, `/ambulance`. All of them go through the
   root layout, so the D7 e2e visits `/login`, the callback, an unknown URL
   and `/ambulance`.
2. **Hydration warnings on the nonce attribute.** Browsers blank `nonce` after
   parsing. The e2e zero-violation test also fails on any console error
   mentioning hydration.
3. **Report bodies that are valid JSON but hostile:** arrays, nested strings
   over 512 characters, numbers given as strings. The Task 4 route test
   covers them.
4. **Dev and prod differ.** The specs project runs `next dev`, while the
   emergency suite runs the standalone production server against
   `/ambulance`. Both must pass with zero violations.
5. **The Radix scroll lock** injects a style only when a modal opens. The e2e
   opens the tenant `Select` (react-remove-scroll) as `specAdmin`.

### Task 4: The violation report endpoint

**Files:**

- Create: `apps/shell/app/api/csp-report/route.ts`
- Test: `apps/shell/app/api/csp-report/route.test.ts`

**Interfaces:**

- Consumes: `CSP_REPORT_PATH` (Task 1). The route location must match it.
- Produces: `POST(request: Request): Promise<Response>`

- [ ] **Step 1: Write failing tests** (spy on `console.warn`):
  - `"logs a sanitised violation and answers 204"`: the body has a
    `document-uri` of `https://h/patients?q=Asha#x`, a `blocked-uri` of
    `inline`, and a `source-file` with a query. The test asserts:
    - one warn call;
    - its parsed JSON is exactly
      `{ msg: "csp violation", "effective-directive", disposition, "document-uri": "https://h/patients", "blocked-uri": "inline", "source-file": <origin+path>, "line-number", "column-number" }`;
    - the raw line does not contain `Asha`.
  - `"truncates long strings to 512 characters"`.
  - `"ignores fields it does not know"`: an extra `script-sample` is not
    logged.
  - `"rejects other content types"` answers 415, `"rejects bodies over 16
KiB"` answers 413 (a streamed body with no `Content-Length`), and
    `"rejects a body that is not a csp-report object"` answers 400, for an
    array, `{}` and `{"csp-report": "x"}`. None of these logs anything.
  - `"keeps non-URL blocked-uri keywords"`: `eval` stays `eval`.
- [ ] **Step 2:** Run it. Expected: FAIL, module not found.
- [ ] **Step 3: Implement.**
  - Read the body through `request.body` with a running byte count and
    abort past 16 KiB.
  - URL fields go through `new URL()`, which yields origin plus pathname. A
    value that does not parse as a URL is kept only if it matches
    `/^[a-z-]+$/` (the keywords). Anything else becomes `"invalid"`.
  - Numbers are accepted only if `typeof === "number"`.
  - Add `export const dynamic = "force-dynamic"` only if the build demands it.
- [ ] **Step 4:** Rerun. Expected: PASS.
- [ ] **Step 5:** Commit `feat(shell): log content security policy violation reports (#1113)`.
