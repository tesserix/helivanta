# Scoped stock register CSV

Issue: [#1232](https://github.com/tesserix/helivanta/issues/1232). Design details and final operating limits: [ADR-0034](../../adr/0034-pharmacy-stock-export.md). Acceptance evidence: [delivery record](../../delivery/2026-10-18-pharmacy-stock-export.md).

Storekeepers can download every matching position from the existing scoped register without loading every JSON page. The file uses the same explicit cutoff and location, product, expiry and balance filters, with all-or-error limits of 1,000 rows and 8 MiB. Unsupported, repeated, empty and pagination parameters are rejected. A header-only CSV represents a genuinely empty result.

The API retains verified tenant membership, stock-read permission, live outlet grants and FORCE RLS. CSV escaping, formula-safe text, exact decimal quantities, no-store responses and attributed generation audits protect the download. Changing scope or filters cancels the browser request and prevents stale downloads. Failures are accessible and retryable.

The existing query is shared, including bounded unique-key lookups needed to avoid a reproduced RLS query-plan timeout. There is no migration or stock mutation. NATS/outbox, Valkey, Temporal and GCS ownership remain unchanged; this is a synchronous read, not a stored report. Sales, margin, valuation, dispensing availability, scheduled exports and immutable accounting snapshots are outside this story.

Acceptance must prove actual CSV bytes against paginated JSON, both countries' saved timezones and addresses, spreadsheet hazards, overflow without partial output, denied scopes, cancellation and audit attribution. Full checks and review precede any separately approved production rollout. The issue remains open until deployed verification.
