# Desktop barcode input — issue #1688

Counter and quarantine receiving accept USB/Bluetooth keyboard-wedge scanners in a labelled barcode field, terminated with Enter (or the Find product button). No timing heuristic or global key capture: ordinary typing, assistive technology and clinical form fields retain their behavior. Camera scanning (#569) is separate.

PharmaConnect owns outlet barcode links. GET and PUT `/pharmacy/pharmacies/{pharmacy}/outlets/{outlet}/catalogue/barcodes/{gtin}` run through the existing Global API and require catalogue read/write respectively plus current outlet reader/editor grants. The PUT body is `{product_id: UUIDv7}`. GS1 GTIN-8/12/13/14 check digits are validated using the shared drug-master rule and stored as GTIN-14, preserving leading zeroes. A composite tenant/outlet/GTIN key and composite product FK enforce one destination per outlet. Links are immutable, audited, and identical retries succeed; conflicting assignments return 409 without overwriting. If no explicit link exists, the existing drug-master catalogue source performs its exact GTIN lookup and the outlet matches only the current published product and formulation versions through their pinned import references. Missing local imports remain unknown; unavailable source data is 503 and multiple eligible local matches are 409. No brand-name or SKU guessing occurs. New routes stay under the existing pharmacy_catalogue release capability; no release flag is enabled. Unknown GET returns `barcode_unknown` only after scope authorization; authorization failures never masquerade as unknown. Withdrawn/inactive matches return `barcode_inactive` and cannot be linked or added.

The shared scanner offers a paged active-product chooser when unknown, showing SKU, brand, manufacturer, pack size and unit of issue for comparison with the physical label. Only catalogue writers can link; other operators receive an actionable request to ask an editor. Linking and scanning never post a sale or stock movement. Pending and failed requests preserve input and offer retry; requests are scoped to tenant, pharmacy and outlet. Context changes discard pending results. The scanner serializes lookup/add operations and returns focus to its field after successful processing.

At the counter each scan adds one full pack converted to units of issue using the catalogue pack size, with visible copy stating this. Availability supplies the current schedule class; non-prescription products with enough sellable stock add immediately, repeated scans increment the same line and invalidate any quote. Regulated products are selected for the existing prescription workflow, never given an inferred prescription. Held/uncertain payments disable scanning. Unavailable safety data adds nothing. A barcode result need not appear on the currently loaded catalogue page.

At receiving a scan selects the product and clears any previous lot using the existing unsaved-work guard. Location, exact manufacturer lot, quantity, printed MRP and receipt evidence remain explicit; the normal receipt command performs the durable posting and replay protection. A product barcode cannot identify a lot. No stock is fabricated from a scan. Supplier shipment and independently scoped operating-duty receiving APIs retain their separate contracts.

Verification: backend HTTP integration tests over real PostgreSQL enforce canonical lookup, replay/conflict, inactive product, route permissions, tenant/outlet isolation, invalid input, audit and concurrent linking. Component tests cover keyboard entry, unknown linking, failures, repeated scans, prescription gates, pending/context cancellation and receiving selection. Run affected suites, typecheck/lint/build, canonical generation and contract inventory checks. Browser/hardware acceptance must be reported separately from component evidence.

Safety review: a wrong pack link could change sold units or identify the wrong medicine. Exact scoped identifiers, check digits, current governed import references, visible pack facts, immutable audited links and the existing pharmacist/prescription/stock/price gates prevent silent substitutions. A receiving scan never guesses a lot or posts physical stock. This change introduces no new jurisdiction or clinical policy and does not assert clinical or regulatory approval.
